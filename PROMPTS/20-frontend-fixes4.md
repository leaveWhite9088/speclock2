# 修复单 20（前端）：核心代理「重建会话」入口

## 背景

核心代理的 pi 会话是长存续的（固定 session-id 自动 resume），全天累积的失败叙事会留在上下文里
持续误导模型（实测它把中午的 better-sqlite3 报错翻出来当"系统性崩溃"的证据）。
后端本批新增 `POST /api/p/{slug}/agent/reset`（归档旧会话 JSONL，下次对话全新上下文），
前端需要入口。DESIGN A1：会话可弃，账本是 SSOT。

## 改动清单

1. **重建会话按钮**：核心代理视图的顶栏模型区旁边（或状态卡）加一个「重建会话」入口，
   带确认弹层（文案：当前对话上下文将归档清空，对话历史仍可在事件日志里查看；核心代理会以全新上下文启动）。
2. 点击 → `POST /api/p/{slug}/agent/reset`（client.ts 补方法）→ 成功后刷新 agent 状态，
   界面提示「会话已重建，下一次对话将从全新上下文开始」。
3. mock.ts 同步：reset 返回 ok。
4. 404（后端未上线路由时）→ 按钮降级隐藏或提示「后端未提供重建会话」。

## 验收自检

1. `npm run build` 通过；mock 模式点重建 → 确认弹层 → 提示成功。
2. live 模式（后端 19 单合并后）：点重建 → agent 状态刷新，下一次发消息核心代理不再记得当天旧对话。
3. 回执：一段话。
