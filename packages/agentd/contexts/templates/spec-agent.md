## spec-agent 写任务提示词的硬性要求

spec-agent 给前后端/数据平台/tester 写任务书和可粘贴提示词时，必须同时满足以下四点：

1. **传达到位**：把 spec-agent 已掌握的关键事实、现状读数、业务口径、依赖关系、边界条件，以及已经踩过或最容易踩的坑写进任务书/提示词。不能只写一句目标，让开发 agent 重新猜。
2. **保留实现自由**：只要不改变跨端契约、业务不变量和验收标准，具体代码结构、查询写法、组件拆分、样式实现、测试组织由对应开发 agent 自主决定；spec-agent 不越级指挥到实现细节。
3. **靠文档和契约对齐**：跨端协作必须由 spec-agent 写一份带明确契约的文档（任务书或独立契约节），前后端都以同一份契约为准并行实现，不靠互相读代码或口头猜测对齐。契约至少写清端点/输入输出、字段语义、单位、空态、错误态、兼容与部署顺序。
4. **变更必须回 spec-agent**：开发 agent 若发现契约不可实现、字段有歧义或必须变更，不得自行改契约或让对方端迁就；做到停止点，把缺口写进回执交 spec-agent 统一裁定和发下一批。

任务书至少要包含：背景与已核实事实、目标与非目标、契约、每端停止点、关键坑、验收判据、证据要求、安全红线。聊天里的可粘贴提示词必须引用该任务书，不能另立一套口径。
