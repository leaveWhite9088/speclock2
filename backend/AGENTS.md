# backend 领地工作规范

本文件约束所有在 backend/ 工作的代理：后端主代理，以及它派发的子代理。
开工前先读本文件。做完工作，按本文件的报告规范交回执。

## 报告语言规范（依据 ASD-STE100 简化技术英语，适用于中文）

目标：读者读一遍就懂。读不懂的报告要重写。

### 句子

- 一句话只说一件事。每句不超过 40 个字。
- 用主动语态。写"我修改了 X"。不写"X 被修改"。
- 报告已完成的事，用"新增了 / 修改了 / 修复了 / 验证了"。
- 少用括号。括号内容超过 15 个字，就写成独立的一句话。

### 段落

- 一段只写一个主题。每段不超过 6 句。
- 操作步骤用编号列表。每步只写一个动作。
- 每条列表不超过两行。

### 用词

- 用常用动词：新增、修改、删除、修复、验证、测试。
- 不用行业黑话："落地""收敛""赋能""打通"不出现。
- 不用程度词："大幅""极大""非常"不出现。用数字代替。
- 术语第一次出现时，用一句话解释它。
- 一个东西只用一个名字。全文不换叫法。
- 不用箭头压缩逻辑（如"A → B → C"）。写成完整的句子。

### 回执结构（固定四段）

1. **完成项**：每项一句话。说清改了什么。
2. **验证**：写命令和结果。每条验证一行。
3. **问题**：有疑问或偏离就写出来。没有就写"无"。
4. **环境**：环境有变化就写。没有就写"无"。

## 工作约束（沿用 DEV-PLAN §5）

- 只写 backend/（任务指定时含 chief/）。
- 不改 DESIGN.md、DEV-PLAN.md、PROMPTS/、web/。
- 提交信息格式：`类型(backend,切片): 摘要`。不 push。
- 全部文件用 UTF-8。界面文案用中文。
- 测试派发只用最小任务（如"只回复一个词：hello"）。
