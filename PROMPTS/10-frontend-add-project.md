# 任务：SpecLock 2 前端——添加项目（选目录 + 选核心代理 LLM）

## 背景

产品需要一个"添加项目"功能：创建时指定**项目目录**（该项目主代理的工作领地）和**核心代理的 LLM**。后端契约 v0.4 已扩：POST /api/projects 接受 `working_dir?/chief_provider?/chief_model?`，新增 `PATCH /api/p/{slug}` 与 `GET /api/fs/dirs?path=`（子目录列表，供目录选择）。项目已有的模型登记抽屉（ModelEntry）是 LLM 下拉的数据源。

## 必读

`DEV-PLAN.md` §2 契约 v0.4（projects 扩字段、PATCH、fs/dirs 三行）；`web/src` 现有模型登记抽屉实现（复用其数据与交互）。

## 任务

1. **「＋ 新建项目」表单**（侧栏项目列表底部或空态；弹窗，风格随现有抽屉）：
   - slug、名称（必填，slug 校验沿用现有规则）；
   - **项目目录**：文本输入（粘贴绝对路径）+「浏览」按钮——走 `GET /api/fs/dirs` 做简易目录选择器（列出子目录点击进入/选中当前）；失焦时校验（后端 422 则行内报错）；
   - **核心代理 LLM**：下拉，选项 = 模型登记里的条目 + 首项"默认（跟随全局配置）"；选中即得 provider/model 两个值；
   - 提交 → POST /api/projects → 成功后项目列表刷新并选中新项目；
2. **项目设置编辑**：项目卡片菜单或设置入口 → 同一张表单复用（目录/LLM 可改）→ PATCH /api/p/{slug}；
3. 侧栏项目条目 hover 显示绑定的目录（省略号截断，title 全文）；
4. mock 模式：fixtures 带新字段，新建走本地状态；
5. 清理与 build 通过；控制台无报错。

## 验收标准（自检全过才算完成）

1. live：UI 新建项目（选一个真实存在的目录 + 选一个登记模型）→ 列表出现、GET /api/p/{slug} 字段正确；
2. 目录不存在 → 表单行内 422 报错，不提交；
3. 编辑项目改目录/模型 → PATCH 生效（curl 可验）；
4. mock 模式全流程可演示；build 通过。

## 约束

- 只动 `web/`；backend 可读不可改；契约疑问走回执；
- 不引入新依赖；提交 `feat(web,add-project): <摘要>`；不要 push；UTF-8。
