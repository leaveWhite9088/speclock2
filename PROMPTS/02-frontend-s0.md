# 任务：SpecLock 2 前端骨架（切片 M1-S0）

## 角色

你是 SpecLock 2 项目的前端主代理，负责 `web/` 目录。产品是"需求到文档到代码的门禁工作台"，核心交互原则：**单页完成一切、对话即时间线、卡片化一切**。当前阶段 M1（账本核心）：先把界面骨架和 API 层立起来。技术栈：Vue 3（Composition API + `<script setup>`）+ Vite + TypeScript；**不引入 vue-router（无路由跳转）、不引入 UI 组件库、不引入状态管理库**，样式手写 CSS（建 tokens 文件）。

## 必读材料（开工前按顺序读完，仓库根目录下）

1. `DESIGN.md`——重点：§15 单页界面（布局 ASCII 图、卡片类型清单、钻取原则）、§8 审批卡片（**§8.1 的卡片长什么样必须照着做**）、§14.3 同项目不切界面的保证、§7.3 轮次定义
2. `DEV-PLAN.md`——全文，尤其是 §2 API 契约 v0（数据形状 Card/Event/Rule/ApiEntry/Block）、§4 的 S0 行、§5 协作规则

## 任务（只做 S0 骨架，禁止超范围实现 S1+ 的功能）

1. 在 `web/` 初始化 Vite + Vue 3 + TypeScript 工程；
2. **单页壳**：按 DESIGN.md §15.1 的 ASCII 布局实现三栏结构：
   - 顶栏：logo、"SpecLock2"、项目切换器（下拉，含切换回调）、右侧"队列 / 仪表盘 / 约定 / 代理"四个入口按钮（S0 打开占位抽屉/面板即可）；
   - 左栏（抽屉组）：模块全景（树占位）、版本链（占位）、规则违反榜（占位）、全局约定（占位）；
   - 中栏（主干）：**轮次时间线**，自底向上渲染模拟的轮次卡；每个轮次卡内含子卡片槽位；
   - 右栏（可折叠）：当前任务包状态（占位）；
3. **审批卡片静态示例**：用 mock 数据渲染一张"待批准"审批卡，样式与信息结构严格照 DESIGN.md §8.1（业务规则 2改1增 / 契约 1改1增 ⚠1破坏性 / 影响面 / 派发预览 / 风险栏 / 三个按钮：批准并派发、打回、展开完整diff——按钮 S0 无实际行为）；
4. **API 层**：`src/api/client.ts` 覆盖契约 v0 **全部端点**的 TypeScript 类型（Card/Event/Rule/ApiEntry/Block 等）与调用函数；
5. **mock 模式**：`src/api/mock.ts` 提供 fixtures（两个项目、一轮 #12 含待批准卡片）；启动时探测 `/api/health`，失败自动切 mock，顶栏显示 `MOCK` 徽标，成功则显示 `LIVE` 并用真实接口取项目列表；
6. Vite dev 代理：`/api` → `http://127.0.0.1:8000`；
7. 组件骨架（占位渲染，文件与 props 结构就位）：`RoundCard`、`ApprovalCard`、`DispatchCard`、`ReceiptCard`、`VerdictCard`；
8. `web/README.md`：安装运行步骤（Windows + Git Bash）。

## 验收标准（自检，全部满足才算完成）

1. `npm install && npm run dev` 启动无错，浏览器控制台无报错；
2. mock 模式（后端未启动）：显示两个模拟项目；切换项目界面随之变化；时间线渲染模拟轮次 #12，内含一张待批准审批卡；
3. live 模式（后端已启动）：徽标变 LIVE，顶栏项目列表来自 `GET /api/projects`；
4. `npm run build` 通过（含类型检查）；
5. 全程单页，无路由跳转；按 README 从零执行可复现。
