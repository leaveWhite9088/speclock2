# 任务：SpecLock 2 前端——模块全景与草稿查看（切片 M1-S1）

## 角色

你是 SpecLock 2 项目的前端主代理，负责 `web/` 目录。S0 骨架已验收通过；本切片把左栏「模块全景」做成真的：真实树 + 新建流 + 草稿查看。技术栈与红线不变：Vue 3 + Vite + TS，无路由、无 UI 库、无状态管理库。

## 必读材料（仓库根目录下）

1. `DESIGN.md` §15.1（左栏定位）、§15.3（钻取原则）、§5.2~5.4（模块四件套、规则、契约的展示语义——**展示要按这些 schema 来**）
2. `DEV-PLAN.md` §2 API 契约 v0（tree / domains / documents / blocks / 草稿读写）

## 任务（只做 S1）

1. **左栏「模块全景」树**：live 模式接 `GET /api/p/{slug}/tree`（S0 已部分接通，补全）；三级展示（业务域 → 文档 → 模块），模块节点带状态徽标（草稿 / 版本号如 1.2.0）；空态显示"暂无业务域"+ 新建入口；
2. **新建流**（单页内浮层或行内表单，禁止路由跳转）：新建业务域（title）→ 域下新建文档（title）→ 文档下新建模块（title），依次调 POST 三端点，成功后树刷新并定位新节点；
3. **草稿查看（只读）**：点击模块节点 → 左栏下方展开或浮层显示草稿四件套：
   - `content_md`：纯文本/pre 展示即可（不引 markdown 库）；
   - `rules`：列表（id / name / detail）；
   - `apis`：每条一张小卡（name、`METHOD /path`、desc、request/response 字段平铺：`name: type (必填)`，嵌套 children 缩进一层即可）；
   - `nfr_md`：纯文本；
4. **mock 模式补齐**：mock 树 + mock 草稿 + 新建走本地状态（不真发请求），保证后端不在时全流程可演示；
5. 顶栏切换项目 → 树与选中状态重置并刷新；
6. 错误处理：接口失败时行内提示（不弹 alert），表单校验（title 非空）。

## 验收标准（自检全过才算完成）

1. live 模式：UI 完成 建 业务域→文档→模块，树正确刷新展示三级结构与状态徽标；
2. 点击模块显示草稿四件套（先用 curl 向该模块 PUT 一份含中文规则/嵌套字段的草稿，再在 UI 查看回显正确）；
3. mock 模式同样走通（建链 + 查看）；
4. `npm run build` 通过；浏览器控制台无报错；全程单页。
