# 任务：SpecLock 2 前端——/model 切换 + 右上角模型功能重构 + 主代理条目增强

## 前提（依赖单）

依赖 `PROMPTS/10-frontend-add-project.md`（添加项目）——**若未完成先完成它**，分开提交。后端本批新增 `POST /api/p/{slug}/agent/model`（契约 v0.5）：`{provider?, model}` → `{ok, model}`，会话未运行 409。

## 背景

参考 mcode（Minimax Code）的体验：CLI 里 `/model` 即可切模型。产品要在**工作台对话输入框**支持同样的命令切换核心代理模型——就这么一个入口，不做配置文件那套。后端已提供切换端点；模型可选项来自现有模型登记（ModelEntry）。

## 任务

1. **输入框 `/model` 命令**（仅核心代理会话；主代理视图输入时回显"模型切换仅对核心代理生效"并不执行）：
   - 输入 `/model` 回车 → 弹出模型选择列表（登记条目 + 当前模型高亮 + "默认（跟随项目配置）"项），点选即切换；
   - 输入 `/model <provider/model>` 回车 → 直接切换；
   - 切换成功 → 对话流系统气泡"模型已切换为 X"；失败（409 未运行等）→ 错误气泡 + 「启动核心代理」快捷按钮（POST /agent/start 后可重试）；
   - `/model` 不进事件日志的对话正文（它是命令不是消息）；
2. **右上角模型功能重构**：当前按钮改为显示**当前生效模型名**（GET /agent 的 model，10s 轮询已有则复用）；点击弹层 = 与 /model 相同的选择列表（同一端点）；原有"模型登记"管理降为弹层里的「管理登记」次级入口；
3. **左栏主代理条目增强**：显示绑定的 harness 名（pi / mcode / claude-code…，登记处来）与最近一次工作时间 + token（receipts telemetry 已有，格式如 `41 分钟 · 180k tokens(估)`）；绑定 mcode 的主代理在 harness 名旁加个小徽标区分；
4. mock 模式同步（fixtures 带模型与遥测字段）；build 通过；控制台无报错。

## 验收标准（自检全过才算完成）

1. live：输入 `/model` → 列表弹层 → 选一个模型 → 系统气泡确认 + 右上角模型名变化（GET /agent 反映）；
2. `/model minimax-cn/MiniMax-M2.7` 直接切换走通；会话未运行时给出启动按钮路径；
3. `/model` 命令本身不出现在对话历史正文里；
4. 左栏主代理条目显示 harness 名与最近遥测；mock 模式可演示；build 通过。
