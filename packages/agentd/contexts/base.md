# 团队基础规则

speclock 创建项目时会把 `project.md` 写到项目根目录（`AGENTS.md`，调度器读），添加执行者时把
`executor.md` 写到执行者目录（`AGENTS.md`）。**只在文件不存在时写**，之后不覆盖，可以自由修改。
本文件只是补充说明。

## 加载范围（实测）

| agent | 自身 cwd 的 AGENTS.md | 父目录的 AGENTS.md |
|---|---|---|
| pi | 加载 | **加载（会向上查找）** |
| mcode | 加载 | 不加载 |
| dsh | 加载 | 不加载 |

所以 mcode / dsh 的规则文件必须放在**它实际启动的那个目录**。
目录见 `agentd.config.json` 里各 agent 的 `cwd`。

## 规则

<!-- 按你的实际情况删改下面的条目；这些都是示例 -->

- 改动任何文件前，先说明你打算改什么、为什么。
- 不要执行 `git push`、不要改 CI 配置、不要碰 `.env`。
- 不确定的事情直接问，不要猜。
- 提交信息用中文，第一行不超过 50 字。
- 任务完成后，用一两句话说明改了什么、验证了什么。

## 完成回执

本调度器会为每次运行生成回执（耗时、模型、上下文占用、健康信号），
所以**不需要**在回答里重复汇报这些。只需要说清：

- 做了什么
- 验证了什么
- 有没有遗留问题
