# 任务：SpecLock 2 前端——chat-first 重构 + M1 收尾整包（S2）

## 角色

你是 SpecLock 2 项目的前端主代理，负责 `web/`。**产品形态已调整为聊天为主界面**：主体是像 ZCode / Kimi Code / Claude Code 那样的中央对话流，功能面板停靠两侧、可整体折叠。本切片一次性完成形态重构 + M1 全部界面。技术栈红线不变：Vue 3 + Vite + TS，无路由、无 UI 库、无状态管理库。

## 前置检查（开工第一步）

`git log` 检查是否存在 `feat(web,s1)` 提交且 S1 范围完成（模块全景树 + 草稿查看，范围见 `PROMPTS/04-frontend-s1.md`）。**若未完成：先完成 S1，再进入 S2**，分开提交。

## 必读材料（仓库根目录下）

1. `DESIGN.md`——§15.1（**新布局 ASCII，严格照它做**）、§8.1（审批卡片的信息结构与样式基准）、§7.3（轮次定义：**轮次 = 对话流中的分段线**）、§9（任务包/任务状态机）、§6.4（技术任务单四字段；直达会话入口只做占位按钮）
2. `DEV-PLAN.md` §2 API 契约 **v0.2**（Card/Package/Task/TechOrder/Convention/Stats 形状、全部新端点）

## 形态要求（参考 ZCode / Kimi Code 一类 AI 编码工作台）

- **中央对话流是绝对主体**：自上而下滚动；底部固定输入框——M1 阶段禁用，占位文案"主主代理将于接入轮上线"，旁边一个「**起草卡片**」按钮（打开结构化表单）；
- **轮次 = 对话流中的分段线**（如 `┈┈ 轮次 #12 · 进行中 ┈┈`），审批卡片等挂在所属轮次下方，内联呈现；
- 左面板（可折叠）：模块全景树（S1 已有，迁入）、版本链、规则违反榜（占位）、全局约定；右面板（可折叠）：当前任务包；顶栏：项目切换器、会话切换器占位 tab、队列/仪表盘/约定/代理入口；**代理面板内放「直达会话」占位按钮**（无逻辑）；
- 视觉从简、信息密度参考终端系工具；中文文案。

## 功能任务（M1 全部界面）

1. **起草卡片表单**：选模块（block）、statement（说明/动机）、rule_ops / api_ops 编辑（增删改，api_ops 需填 key 与 breaking）→ `POST cards` → 卡片以 §8.1 样式内联到当前轮次（待批准态；**破坏性强制展开**，其余默认折叠计数）；
2. **批准 / 打回** → 卡片态变化、轮次分段线推进、版本链面板 +1、任务包面板出现新包；
3. **任务包面板**：任务状态徽标（queued/dispatched/running/reported/auditing/done/rejected/timeout，timeout 标红）；每任务操作：模拟派发（可填 watchdog 分钟数，便于演示超时）、回执表单（files_changed/self_check/summary）、审计按钮（pass/fail）；
4. **技术任务单建单表单**（intent/scope/baseline/acceptance）→ `POST tech-orders` → 任务包出现 origin=tech；
5. **全局约定面板**：查看当前版、编辑草稿、批准（填说明/动机）；
6. **仪表盘**：`GET stats` 渲染计数卡；
7. **mock 模式同步补齐以上全部**（fixtures 含轮次/卡片/包/任务/约定/统计），LIVE/MOCK 徽标与自动探测沿用；
8. 项目切换 → 全部状态重置刷新。

## 验收标准（自检全过才算完成）

1. live：建链 → 起草一张含破坏性 API 变更的卡 → 渲染符合 §8.1 → 批准 → 分段线推进 + 版本链 +1 + 任务包出现；
2. 回执/审计/超时可点通（dispatch 设 1 分钟等 timeout，或引用后端测试覆盖说明）；
3. 技术单建单走通；约定编辑+批准走通；仪表盘有数；
4. **chat-first 形态**：对话流为主、两侧面板可折叠、全程单页无路由；`npm run build` 通过；控制台无报错；
5. mock 模式同样全流程可演示。
