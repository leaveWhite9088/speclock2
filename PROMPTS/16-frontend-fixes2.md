# 任务：前端修复单——流式回复跨视图存活 + 发送占用控制 + 会话选择器 + 验收清理入口

## 问题背景（2026-10-15 用户实测复现）

1. **切走再回来，正在生成的回复消失**：核心代理思考中用户切到别的会话视图再切回，正在打字的那条回复不见了（但后台还在继续写）。现状：`streamText` 是全局 ref，SSE 一直在累积，但对话区在视图切换时会从事件日志重建气泡——进行中的回复还没落 `chat.chief` 事件，重建后就不显示了。
2. **核心代理没回完还能继续发消息**：`sendToCore` 有 streaming 守卫，但**主代理视图的输入没有同样守卫**（且核心代理未回完时用户感知不到"正在回复"状态，切走再回来连状态都看不见）。
3. **添加主代理的 CLI 会话选择太乱**：列出了该 harness 在所有目录下的历史会话（后端已加 `?cwd=` 过滤参数，本单接上）；且除了选历史的，还应能选"开始新对话"（= 不绑定 CLI 会话）。
4. **待验收/运行中标签依旧迷惑**：mctest 项目明明没人在干活，主代理条目上却挂着"待验收"——数据源是测试遗留的 reported 任务（后端已提供 `POST /api/p/{slug}/audit-all` 批量清理端点）。

## 任务

1. **流式回复跨视图存活**：进行中的回复（streamText）与视图解耦——它是项目级状态；对话区重建气泡时，若 streamText 非空则在底部渲染进行中气泡（打字机样式），切走再回来必须还在；落定（message_final）后归入历史；
2. **发送占用控制**：核心代理 streaming 期间，**所有**输入路径（核心视图、主代理视图）统一禁用发送并显示"核心代理正在回复…"+「停止」按钮；streaming 状态跨视图可见（如侧栏核心代理条目上转圈）；主代理视图输入若是独立通道，明确提示"该主代理由任务派发驱动，对话请回核心代理"；
3. **CLI 会话选择器**：添加/编辑主代理表单里，会话列表改调 `GET /api/cli-sessions?cwd=<项目working_dir>`，只列当前项目目录下的会话；列表首项固定「开始新对话」（= 清空绑定，提交 null）；每项显示时间与 id 摘要；项目未绑定 working_dir 时该区域显示"先在项目设置里绑定目录"；
4. **待验收清理入口**：顶栏或主代理条目的"待验收"N 徽标点击 → 弹层列出 reported 任务（任务号/主代理/摘要）→「全部标记为已验收」调 audit-all → 徽标清零；主代理条目的"运行中"计数只统计 dispatched/running，不再把 queued/reported 算进去（若上轮已修则核对即可）。

## 验收自检

1. live：核心代理长回复期间切走再切回，进行中回复仍在且继续增长；期间主代理视图输入被禁用并显示状态；
2. `/model` 列表选 mcode 条目（后端已修 provider）切换成功不再 502；
3. 添加主代理：会话列表只出现当前项目目录下的；选「开始新对话」提交成功；
4. mctest 的待验收徽标经弹层一键清理后消失；build 通过；控制台无报错。
